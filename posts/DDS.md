# DDS、TCP 与 UDP：机器人通信机制学习笔记

## 一、前言

在机器人系统开发中，不同模块之间需要进行大量的数据交互。例如，机器人主控板需要向上位机发送运行状态，传感器需要实时传输采集的数据，导航模块需要接收速度控制指令。这些功能都离不开网络通信技术。

在学习 ROS2 分布式通信的过程中，接触到了 DDS、TCP 和 UDP 这三种重要的通信技术。它们在通信层次、工作机制以及应用场景上有所不同。理解它们之间的关系，有助于进一步掌握 ROS2 的通信机制，也能为后续机器人上位机与主控板之间的通信开发打下基础。

## 二、TCP 通信协议

### 1. TCP 是什么？

TCP（Transmission Control Protocol，传输控制协议）是一种面向连接的、可靠的传输层协议。

在正式传输数据之前，通信双方需要先建立连接。TCP 通过三次握手建立连接，通过确认应答、序列号、超时重传等机制保证数据可靠传输。

### 2. TCP 的主要特点

- **面向连接：** 通信双方在传输数据前需要建立连接。
- **可靠传输：** 通过确认应答和超时重传机制，尽可能保证数据完整到达。
- **有序传输：** 接收端能够按照正确顺序重新组织数据。
- **流式传输：** TCP 传输的是连续字节流，没有天然的消息边界，需要应用层自行设计数据帧。
- **拥塞控制：** 根据网络状况调整数据发送速率。

### 3. TCP 三次握手

TCP 建立连接主要分为三个步骤：

1. 第一次握手：客户端向服务器发送 SYN 请求，申请建立连接。
2. 第二次握手：服务器收到请求后，回复 SYN + ACK。
3. 第三次握手：客户端收到响应后，再发送 ACK，连接建立完成。

连接建立后，双方就可以开始进行数据传输。

### 4. TCP 在机器人中的应用

在机器人系统中，TCP 常用于对数据完整性要求较高的通信场景，例如：

- 上位机与机器人主控板之间的数据交互。
- 机器人参数配置和设备管理。
- 控制指令、任务信息的传输。
- 日志文件和运行数据的传输。

TCP 的优势是可靠性较高，但连接管理、确认应答和重传机制也会带来一定的通信开销和延迟。

## 三、UDP 通信协议

### 1. UDP 是什么？

UDP（User Datagram Protocol，用户数据报协议）是一种无连接的传输层协议。

与 TCP 不同，UDP 在发送数据之前不需要建立连接，也不需要通过确认应答来保证数据一定到达。发送方可以直接将数据封装成数据报并发送给接收方。

### 2. UDP 的主要特点

- **无连接：** 发送数据前不需要建立连接。
- **传输开销小：** 协议头部较简单，通信效率较高。
- **实时性较好：** 不需要等待确认应答，适合对延迟敏感的应用。
- **不保证可靠性：** 数据可能出现丢失、重复或乱序。
- **数据报传输：** 保留数据报边界，一次发送对应一个数据报。

需要注意的是，UDP 本身不提供可靠传输机制。如果应用需要可靠性，可以在应用层自行设计确认、重传和排序机制。

### 3. UDP 在机器人中的应用

UDP 在机器人系统中常用于对实时性要求较高的场景，例如：

- 高频传感器数据传输。
- 激光雷达、点云等数据的网络传输。
- 机器人实时状态信息广播。
- 对延迟敏感的视频或音频传输。

例如，在机器人运行过程中，传感器会持续产生大量数据。如果每一帧数据都必须等待确认后再发送，可能会增加通信延迟。因此，在某些允许少量数据丢失的场景下，UDP 是一种合适的选择。

## 四、DDS 通信中间件

### 1. DDS 是什么？

DDS（Data Distribution Service，数据分发服务）是一种面向数据的分布式通信中间件标准，由 OMG（Object Management Group）制定。

DDS 的核心思想是数据分发，而不是让通信双方直接建立固定的点对点连接。

DDS 采用发布者（Publisher）和订阅者（Subscriber）的通信模型。发布者负责发布数据，订阅者负责订阅自己需要的数据，DDS 中间件负责数据的发现、匹配和传输。

### 2. DDS 的主要特点

- **分布式通信：** 支持多个节点在不同设备之间进行通信。
- **自动发现：** 通信节点可以自动发现网络中的其他参与者。
- **发布订阅模型：** 发布者与订阅者不需要直接建立点对点关系。
- **QoS 服务质量策略：** 可以根据业务需求配置可靠性、历史数据、数据持久性等策略。
- **松耦合：** 发布者不需要知道具体有哪些订阅者。

### 3. DDS 的通信模型

DDS 主要包含以下几个核心概念：

- **DomainParticipant：** 域参与者，代表一个应用程序参与 DDS 通信。
- **Publisher：** 发布者，负责发布数据。
- **Subscriber：** 订阅者，负责接收订阅的数据。
- **DataWriter：** 数据写入者，负责将数据写入 DDS。
- **DataReader：** 数据读取者，负责读取 DDS 中的数据。
- **Topic：** 主题，用于描述数据的名称和类型。

通信过程可以简单理解为：

1. 发布者创建 Topic。
2. DataWriter 将数据发布到对应 Topic。
3. 订阅者发现对应 Topic。
4. DataReader 接收并读取数据。
5. DDS 根据配置的 QoS 策略完成数据分发。

### 4. DDS 的 QoS 策略

QoS（Quality of Service，服务质量）是 DDS 的重要功能，可以根据不同业务需求调整通信行为。

常见的 QoS 策略包括：

- **Reliability（可靠性）：** 分为 BEST_EFFORT 和 RELIABLE 两种，分别对应尽力而为和可靠传输。
- **Durability（持久性）：** 决定新加入的订阅者是否能够接收到之前发布的数据。
- **History（历史记录）：** 控制数据历史缓存的保存方式和数量。
- **Deadline（截止时间）：** 用于约束数据更新的时间间隔。
- **Liveliness（活跃性）：** 用于判断通信参与者是否仍然处于活跃状态。

通过这些策略，可以针对不同的机器人业务场景选择合适的通信方式。

## 五、DDS、TCP、UDP 三者之间的关系

DDS、TCP 和 UDP 虽然都与网络通信有关，但它们并不处于完全相同的技术层次。

TCP 和 UDP 属于传输层协议，主要负责网络数据的传输。

DDS 属于通信中间件，建立在底层网络传输能力之上，为应用程序提供数据分发、节点发现和 QoS 等功能。

DDS 可以通过不同的传输实现进行数据通信，其中常见的 DDSI-RTPS 实现通常使用 UDP 作为底层传输方式，也可以根据具体实现和配置使用 TCP 等传输方式。
